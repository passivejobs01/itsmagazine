# 안 쓰는 안드로이드 폰으로 홈서버 만들기 — 설치 가이드

서랍에 있는 구형 안드로이드 폰에 **Termux**를 올려서 **파일 서버 + 미디어 서버 + 카메라**로 쓰고,
**집 밖에서도 같은 주소로 접속**하게 만드는 구성입니다.
루팅하지 않고, **폰을 평소처럼 쓸 수 있는 상태 그대로** 진행합니다.

영상에서 빠르게 지나간 **커맨드와 순서**를 여기 적어둡니다.

## 완성 모습

```
폰 전원 ON
 ├ (안드로이드) Tailscale 항상 켜진 VPN   → 어디서든 같은 주소
 ├ (안드로이드) IP Webcam                 → 카메라 (쓸 때만)
 └ (Termux:Boot) 부팅 스크립트
      ├ termux-wake-lock                  → 절전 진입 차단
      └ runit ──┬── sshd      (8022)      → 터미널
                ├── dufs      (8092)      → 파일 (업로드/다운로드/WebDAV)
                ├── Jellyfin  (8096)      → 영상 스트리밍
                ├── Syncthing (8384)      → PC와 폴더 동기화 (구글 드라이브 대신)
                ├── 대시보드  (8095)      → 카메라 + 상태를 한 페이지에
                ├── 센서      (8093)      → 나침반·조도·기압 (부록 A)
                └── 제어판    (8094)      → 진동·손전등·알림·음성 (부록 A)
```

**서비스가 죽으면 runit이 자동으로 되살리고, 폰을 재부팅해도 알아서 다 뜹니다.**

## 시작하기 전에 — 구조 한 장

설치하다 보면 **"데비안을 깔았는데 왜 이건 안 되지?"** 하는 순간이 반드시 옵니다.
그림 한 장만 먼저 보고 가면 그때 헤매지 않습니다.

```
          [ 사용자 공간 — 우리가 만지는 건 전부 여기 ]

   안드로이드 앱들        Termux ◀── 이것도 그냥 "앱 하나"
                            │
                            ├─ ⓐ 네이티브 : sshd · dufs · python · node
                            │
                            └─ ⓑ proot ─▶ 데비안 : Jellyfin
   ──────────────────────────────────────────────────────
          [ 커널 공간 — 하나뿐, 바꿀 수 없음 ]
                    리눅스 커널 (폰에 박혀 있는 것)
   ──────────────────────────────────────────────────────
                       폰 하드웨어
```

### 기억할 건 세 줄입니다

| | |
|---|---|
| ① | **Termux는 OS가 아니라 앱입니다.** 그 안의 모든 것이 **앱 권한**으로 돕니다 |
| ② | **데비안은 폴더 하나입니다.** `proot` 가 그 폴더를 `/` 로 보이게 해줄 뿐입니다 |
| ③ | **커널은 폰 것 하나뿐입니다.** 데비안을 깔아도 **커널은 안 깔립니다** |

③이 의외일 수 있는데, 직접 확인할 수 있습니다 — 데비안 안에서:

```bash
dpkg -l | grep -c linux-image     # → 0
```

> 🔑 **리눅스 배포판 = 커널이 아니라 "유저랜드"** 입니다. libc·셸·`apt`·`/usr` 구조가
> 배포판이고, **커널은 폰 것을 빌려 씁니다.** 가상머신과 갈리는 지점이 정확히 여기입니다
> (VM은 자기 커널을 따로 부팅합니다 → 그래서 VM에서는 도커가 됩니다).

### 그래서 되는 것과 안 되는 것이 깔끔하게 갈립니다

| | 이유 |
|---|---|
| ✅ `apt install` 이 된다 | **파일을 폴더에 푸는 일**이라 커널과 무관 |
| ✅ 8000번대 포트 서버 | 앱 권한으로 충분 |
| 🔴 도커가 안 된다 | **커널이 허락해야 하는 일** |
| 🔴 카메라·영상 디코더 직접 접근 불가 | 〃 |
| 🔴 **1024 미만 포트(80·443) 불가** | 〃 |

**폴더를 아무리 그럴듯하게 꾸며도 커널은 속지 않습니다.**
전체 목록은 [11장](#11-안-되는-것--미리-알아두세요)에 있습니다.

## 1. Termux 기본 설정

Termux를 처음 실행하고 아래를 차례로 입력합니다.

```bash
# 패키지 목록·본체 최신화 (처음엔 몇 분 걸립니다)
pkg upgrade -y

# 필요한 것 설치
pkg install -y openssh termux-services termux-api python
#                ^SSH   ^서비스 관리    ^폰 기능 연결  ^8장 대시보드가 씁니다

# 저장소(사진·다운로드 폴더) 접근 권한 — 권한 팝업이 뜨면 허용
termux-setup-storage
```

> 🔑 **"아까 앱으로 깐 Termux:API 를 왜 또 까나요?"** — **같은 이름이지만 다른 물건입니다.**
>
> **앱**은 안드로이드에 물어봐 주는 **창구**고, **패키지**는 그 창구를 부르는 **명령어**입니다.
> 둘 중 하나만 있으면 아무 일도 일어나지 않습니다 — **에러도 잘 안 납니다.**

| | 앱 (F-Droid) | 패키지 (`pkg install`) | 둘 다 필요한가 |
|---|---|---|---|
| **Termux:API** | ✅ 있음 | ✅ `termux-api` (명령 84개) | 🔴 **예 — 둘 다** |
| **Termux:Boot** | ✅ 있음 | ❌ **없음** | 앱만 |
| **Termux:Widget** | ✅ 있음 | ❌ **없음** | 앱만 |
| `termux-services` | ❌ 없음 | ✅ 패키지만 | 패키지만 |

> ⚠️ **`pkg install termux-widget` 이나 `termux-boot` 은 찾아도 안 나옵니다.** 없는 게 정상입니다.
> 🔑 **앱과 패키지가 둘 다 있는 건 `Termux:API` 하나뿐**이라, 헷갈리는 지점도 거기 하나입니다.

내 사용자 이름을 확인해 둡니다. **폰마다 다릅니다.**

```bash
whoami
```

> `u0_a123` 같은 값이 나옵니다. **앞으로 이 값을 쓰므로 적어두세요.**
> 이 문서에서는 `<내계정>` 으로 표기합니다.

## 2. Tailscale — 주소를 하나로 고정

🔑 **이걸 제일 먼저 하는 이유가 있습니다.** 공유기가 주는 폰 IP(`192.168.x.x`)는
**네트워크가 바뀌거나 폰이 재접속하면 달라집니다.** 그 주소로 설정을 해두면
나중에 전부 고쳐야 합니다. Tailscale을 먼저 깔면 **이 문서 끝까지 주소 하나**로 갑니다.

| | 공유기가 주는 IP | **Tailscale 주소** |
|---|---|---|
| 집 안 | `192.168.x.x` | `100.x.x.x` |
| 집 밖 | ❌ 안 됨 | ✅ **같은 주소** |
| 바뀌나 | 🔴 **바뀝니다** | 안 바뀝니다 |
| 공유기 설정 | 포트포워딩 필요 | **필요 없음** |

그래서 아래부터 나오는 **`<폰주소>` 는 전부 Tailscale 주소**를 말합니다.

1. 폰에서 **Tailscale 앱 실행 → 로그인 → 연결**
2. PC에도 [Tailscale](https://tailscale.com/download) 설치 → **같은 계정으로 로그인**

폰의 고정 주소를 확인합니다 (Tailscale 앱 첫 화면 또는 PC에서):

```powershell
tailscale status
```

`100.x.x.x  <폰이름>` 형태로 나옵니다. 이 문서에서는 `<폰주소>` 로 표기합니다.

### 🔴 부팅 시 자동 연결 설정

```
설정 → 연결 → 기타 연결 설정 → VPN → Tailscale 옆 ⚙️
   → "항상 켜진 VPN"  ✅ 켜기
   → "VPN 없이 연결 차단"  🔴 끄기
```

> 🔴 **"VPN 없이 연결 차단"을 켜면 안 됩니다.** Tailscale이 못 뜨는 순간
> **폰의 모든 네트워크가 끊깁니다.** 집 내부 접속으로도 못 들어가서
> 폰을 직접 만져야 복구됩니다.

## 3. SSH — PC에서 폰에 접속

### 3-1. 비밀번호 설정 후 sshd 켜기

```bash
# 접속용 비밀번호 설정
passwd

# runit에 sshd 등록 (부팅 시 자동 시작)
sv-enable sshd
```

> 🔴 **`unable to change to service directory` 에러가 나면** — Termux를 완전히 종료하고
> (`exit` 후 알림에서 종료) **다시 실행**한 뒤 `sv-enable sshd` 를 다시 하세요.
> `termux-services`를 설치한 **그 세션에서는 환경변수가 아직 안 잡혀 있습니다.**

확인:

```bash
sv status sshd
```

`run: sshd: (pid ...)` 가 나오면 정상입니다.

> 🔴 **`down: sshd ... want up` 이 반복되면** — 예전에 수동으로 띄운 sshd가 포트를 잡고
> 있는 것입니다. `pkill sshd` 후 몇 초 기다리면 runit이 알아서 올립니다.

### 3-2. PC에서 접속

2장에서 확인한 **Tailscale 주소**로 들어갑니다.

```powershell
ssh -p 8022 <내계정>@<폰주소>
```

> 📌 포트는 **8022**입니다. 안드로이드 앱은 1024 미만 포트를 쓸 수 없어서
> Termux의 sshd는 8022를 씁니다.

### 3-3. 비밀번호 없이 접속 (권장)

#### 먼저 — 무슨 일이 일어나는 건가

열쇠 꾸러미를 만들어서 **자물쇠는 폰에 달고, 열쇠는 PC에만 둡니다.**

| | 파일 | 어디에 |
|---|---|---|
| 🔓 **공개키** (자물쇠) | `id_ed25519.pub` | **폰에 등록합니다.** 남에게 보여줘도 안전합니다 |
| 🔑 **개인키** (열쇠) | `id_ed25519` | 🔴 **PC 밖으로 내보내지 않습니다.** 복사도, 전송도 하지 않습니다 |

접속할 때 폰은 **그 자물쇠로 잠근 문제**를 내고, PC가 개인키로 풀어서 "내가 주인이다"를 증명합니다.
🔑 **개인키 자체는 네트워크를 타고 가지 않습니다.** 그래서 비밀번호보다 안전합니다 —
비밀번호는 접속할 때마다 **보내야 하지만**, 열쇠는 **보내지 않고 증명만** 합니다.

폰 쪽에 생기는 `~/.ssh/authorized_keys` 는 **달아둔 자물쇠 목록**입니다.
**한 줄 = PC 한 대.** 노트북·데스크톱을 둘 다 쓰면 **두 줄**이 됩니다.

#### 실행

```powershell
# ① 키가 없다면 먼저 생성 (이미 있으면 건너뜁니다)
ssh-keygen -t ed25519

# ② 공개키를 폰에 등록 — 🔑 이때 비밀번호를 묻는 건 이번 한 번뿐입니다
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 8022 <내계정>@<폰IP> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

> 🔴 **①에서 "이미 있는데 덮어쓸까요?(overwrite)" 가 나오면 `n` 을 누르세요.**
> 덮어쓰면 **그 열쇠를 쓰던 다른 서버에 전부 못 들어갑니다.** 이미 있으면 그대로 쓰면 됩니다.
> 💡 Git Bash 를 쓰신다면 `type` 대신 `cat ~/.ssh/id_ed25519.pub` 입니다.

②가 하는 일을 쪼개면 이렇습니다.

| 부분 | 하는 일 |
|---|---|
| `type ...id_ed25519.pub` | PC의 **공개키 파일을 읽어서** |
| `\| ssh -p 8022 ...@...` | **폰에 접속해 그 내용을 넘깁니다** (여기서 비밀번호 1회) |
| `mkdir -p ~/.ssh` + `chmod 700` | 폴더를 만들고 **주인만 드나들게** 권한을 조입니다 |
| 🔴 `cat >> ~/.ssh/authorized_keys` | 넘어온 공개키를 **목록 끝에 덧붙입니다** |
| `chmod 600 ~/.ssh/authorized_keys` | 파일도 **주인만 읽게** 조입니다 |

> 🔴 **`>>` 를 `>` 로 쓰면 안 됩니다.** `>` 는 **덮어쓰기**라, 이미 등록해둔 다른 PC가
> **그 순간 못 들어오게 됩니다.** 화살표 두 개가 "**덧붙이기**"입니다.
>
> 🔑 **`chmod` 를 빼면 안 되는 이유** — sshd 는 권한이 느슨하면 **그 키를 조용히 무시합니다.**
> 에러를 내지 않고 **그냥 비밀번호를 다시 물어봅니다.** "키를 등록했는데 계속 비밀번호를
> 묻는다"는 증상의 가장 흔한 원인이 이것입니다.

#### 확인

```powershell
ssh -p 8022 <내계정>@<폰IP>
```

**비밀번호를 안 물으면 성공입니다.** 계속 묻는다면 폰에서 이렇게 봅니다.

```bash
ls -ld ~/.ssh                 # drwx------ 여야 합니다
ls -l  ~/.ssh/authorized_keys # -rw------- 여야 합니다
cat    ~/.ssh/authorized_keys # ssh-ed25519 AAAA... 로 시작하는 줄
wc -l  ~/.ssh/authorized_keys # 줄 수 = 등록한 PC 대수
```

> ⚠️ 내용이 `ssh-ed25519` 로 시작하지 않거나 줄이 중간에 끊겨 있으면, **붙여넣다 깨진 것**입니다.
> 그 줄을 지우고 ②를 다시 실행하세요.

#### 📌 비밀번호 로그인은 그대로 둡니다

키가 생겼다고 **비밀번호를 막지는 않습니다.** 폰은 집 안(또는 Tailscale) 안에만 있어서
바깥에 노출돼 있지 않고, 🔴 **PC가 고장나 열쇠를 잃으면 들어갈 방법이 없어지기 때문**입니다.

### 3-4. 접속 이름 등록 — `ssh phone`

지금까지는 접속할 때마다 **포트·계정·주소를 전부** 쳐야 했습니다.

```powershell
ssh -p 8022 <내계정>@<폰주소>      # 😩 매번 이걸
ssh phone                          # 🔑 이렇게 줄입니다
```

PC의 **`C:\Users\<사용자>\.ssh\config`** 파일에 아래를 추가합니다. (파일이 없으면 새로 만듭니다.
확장자는 **없습니다** — 메모장으로 저장하면 `config.txt` 가 되기 쉬우니 주의하세요.)

```
Host phone
  HostName <폰주소>
  User <내계정>
  Port 8022
  IdentityFile ~/.ssh/id_ed25519
  ServerAliveInterval 30
```

| 줄 | 뜻 |
|---|---|
| `Host phone` | 🔑 **내가 붙이는 별명입니다.** `phone` 대신 아무 이름이나 됩니다 |
| `HostName` | 실제 주소. **Tailscale 주소(`100.x.x.x`)** 를 권합니다 — 집·밖 어디서든 같습니다 |
| `User` / `Port` | 3-1 에서 쓰던 계정과 `8022` |
| `IdentityFile` | 3-3 에서 만든 **개인키**. 이걸 적어두면 열쇠를 자동으로 찾습니다 |
| `ServerAliveInterval 30` | 30초마다 신호를 보내 **연결이 조용히 끊기는 것을 막습니다** |

> 💡 **집 안에서만 쓸 거라면** `HostName` 에 **집 안 IP(`192.168.x.x`)** 를 적어도 됩니다.
> 폰 IP 는 Termux 에서 `termux-wifi-connectioninfo` 로 확인합니다.
> 🔴 다만 **공유기가 주는 주소라 바뀔 수 있습니다** — 그때는 이 파일도 같이 고쳐야 합니다.
> 공유기에서 **고정 할당(DHCP 예약)** 을 걸어두면 안 바뀝니다.
>
> 🔑 **여러 대를 쓸 거면 블록을 여러 개 두면 됩니다** — `Host phone`, `Host phone-lan` 처럼
> 이름만 다르게 적어두고 상황에 따라 골라 쓰는 방식이 편합니다.

이제 **`ssh phone`** 으로 들어가집니다. `scp` 도 같은 별명을 씁니다 — `scp 파일 phone:~/`.

### 스크립트 내려받기 — 한 번에

이 가이드에 나오는 긴 설정 파일들은 **저장소에 그대로 올려뒀습니다.**
직접 타이핑하지 말고 받아서 쓰세요. **받아주는 스크립트 하나만 받으면 됩니다.**

```bash
cd ~

# ① 받아주는 스크립트를 먼저 받고

# ② 🔴 무엇을 하는 스크립트인지 한 번 읽어보고

# ③ 실행합니다

```

> 🔑 **실행 권한(`chmod +x`)도 같이 걸어줍니다.** 이게 빠지면 나중에 **Termux:Boot 이
> 부팅 스크립트를 그냥 무시합니다** — 에러가 안 나서 원인을 찾기 어려운 자리입니다.

#### 💡 ③에서 앞에 `sh` 를 꼭 붙여야 하나요?

**네, 붙이세요.** `curl` 로 막 받은 파일에는 **실행 권한이 없습니다.**

```
-rw-------   get-files.sh      ← 방금 받은 상태. x 가 없습니다
```

그래서 `~/get-files.sh` 라고만 치면 **`Permission denied`** 가 납니다.

| 방법 | |
|---|---|
| **`sh ~/get-files.sh`** | 🔑 **권장.** 파일 권한과 **무관하게** 됩니다 |
| `chmod +x ~/get-files.sh` 후 `~/get-files.sh` | 한 단계가 더 필요합니다 |

**차이는 "누가 실행하느냐"입니다.** 앞에 `sh` 를 붙이면 **`sh` 를 실행하고 파일은 그냥
입력으로 넘기는** 것이라, 파일이 실행 가능한지는 아무도 묻지 않습니다. 반면
`~/get-files.sh` 는 **파일 자체를 실행**하려는 것이라 `x` 권한이 있어야 합니다.

🔑 **그럼 왜 `start-dufs.sh` 같은 건 `chmod +x` 를 걸까요** — **사람이 안 부르기 때문입니다.**
그 파일들은 `runit` 과 `Termux:Boot` 이 **직접 실행**합니다. 앞에 `sh` 를 붙여줄 사람이
없으니 **파일에 권한이 있어야** 합니다. `get-files.sh` 는 손으로 한 번 부르고 마는
파일이라 권한이 없어도 됩니다.


#### 🔴 왜 `curl ... | sh` 로 바로 실행하지 않나

인터넷에서 흔히 보는 `curl 주소 | sh` 는 **받은 내용을 보지도 않고 그대로 실행**합니다.
이 가이드는 **받고 → 읽고 → 실행**, 세 단계로 나눠 두었습니다.

| | |
|---|---|
| 🔴 **내용을 모르고 실행하게 됩니다** | 주소가 바뀌었거나 저장소가 남의 손에 넘어가도 알 수 없습니다 |
| ⚠️ **중간에 끊기면 반쪽만 실행됩니다** | 파이프는 받는 대로 바로 실행해서, 끊긴 지점까지가 이미 돌아갑니다 |

**홈서버를 직접 운영한다는 건 "내 기기에서 무엇이 도는지 내가 안다"는 뜻입니다.**
②의 `cat` 한 줄이 그 습관의 시작입니다.

> 💡 **받기는 `.part` 로 받아 성공했을 때만 제자리로 옮깁니다.** 중간에 끊겨도
> **반쯤 받은 파일이 남지 않고**, 다시 실행하면 실패한 것만 다시 받습니다.
> ✅ **여러 번 실행해도 안전합니다.**

> 📌 **내용이 궁금하면 `cat ~/start-dufs.sh` 로 언제든 볼 수 있습니다.**
> 아래 각 장에도 **무엇을 하는 파일인지** 설명해 두었습니다.
> 직접 타이핑하고 싶다면 각 장의 "직접 만들기" 부분을 참고하세요.

## 4. 파일 서버 — dufs

브라우저로 들어가면 **업로드·다운로드·삭제**가 되고, 동시에 **WebDAV 서버**로도
동작합니다. 3.5MB짜리 단일 실행 파일이라 폰에 부담이 없습니다.

### 4-1. 한 줄로 — 설치부터 첫 실행까지

```bash
sh ~/install-dufs.sh
```

이 스크립트 하나가 **설치 → 아이디·비밀번호 → 실행**을 차례로 합니다.

```
파일 서버(dufs) 설치
────────────────────────────────────────────
  · CPU aarch64 → aarch64-unknown-linux-musl
  · 내려받는 중 (v0.47.0)
  ✅ 설치 완료 — dufs 0.47.0

  로그인 정보를 정합니다.
  아이디: ______
  비밀번호: (안 보입니다)
  한 번 더:
  ✅ 저장했습니다
```

**마지막에 멈춰 있는 게 정상입니다.** 서버가 떠 있는 상태입니다 —
브라우저로 **`http://<폰주소>:8092/`** 에 접속해 **로그인되면 성공**입니다.
확인했으면 **`Ctrl+C`** 로 멈춥니다. 7장에서 자동 실행으로 등록할 겁니다.

> 🔑 **아이디·비밀번호를 화면에서 받는 이유** — 명령으로 치면 그 비밀번호가
> **명령 기록(`~/.bash_history`)에 그대로 남습니다.** 물어보고 바로 파일에 넣으면
> 어디에도 안 남습니다. 비밀번호는 **입력할 때 화면에 찍히지도 않습니다**(촬영·화면공유 대비).
>
> ✅ **여러 번 실행해도 안전합니다.** 이미 설치돼 있으면 건너뛰고, 아이디·비밀번호도
> 이미 있으면 그대로 둡니다. 🔑 **바꾸고 싶으면** `~/.webdav_user` · `~/.webdav_pass`
> 를 지우고 다시 실행하면 다시 물어봅니다.

#### 📂 이 스크립트가 실제로 하는 일

| 단계 | 하는 일 |
|---|---|
| ① **CPU 판별** | `uname -m` 으로 보고 **맞는 파일을 알아서 고릅니다.** 폰은 보통 `aarch64` 지만 오래된 기기는 `armv7l` 입니다 |
| ② **설치** | 받아서 압축을 풀고 `~/dufs/dufs` 로 옮긴 뒤 **받은 압축파일은 지웁니다** |
| ③ **검증** | `dufs --version` 이 실제로 되는지 봅니다 — 🔑 **CPU 가 안 맞는 파일을 받으면 여기서 걸립니다** (안 보면 7장에서 "서비스가 안 뜬다"로 나타납니다) |
| ④ **아이디·비밀번호** | 없을 때만 묻고 `~/.webdav_user` · `~/.webdav_pass` 에 **권한 600** 으로 저장 |
| ⑤ **실행** | `~/start-dufs.sh` 로 넘깁니다 |

**버전·포트를 바꾸려면** 앞에 붙이면 됩니다.

```bash
DUFS_VERSION=0.48.0 PORT=9000 sh ~/install-dufs.sh
```

📌 최신 버전은 [릴리스 페이지](https://github.com/sigoden/dufs/releases)에서 확인하세요.


### 4-2. 🔴 인증 없이는 열지 않습니다

위에서 아이디·비밀번호를 **건너뛸 수 없게** 만든 이유가 있습니다.
이 서버는 **폰 저장소 전체(`/storage/emulated/0`)** 를 공개합니다 — **사진도 포함입니다.**
인증을 빼면 **같은 Wi-Fi 에 있는 누구나** 들어와서 보고, 받고, 지울 수 있습니다.

### 4-3. 실행 스크립트 — `start-dufs.sh`

4-1의 마지막 단계에서 넘어가는 파일입니다. 하는 일은 두 가지입니다.

1. 저장해둔 아이디·비밀번호를 읽어 **설정 파일(`~/dufs/dufs.yaml`)을 만들고**
2. 그 설정으로 dufs를 띄웁니다 — 포트 **8092**, 공개 폴더 `/storage/emulated/0`

> 🔑 **비밀번호를 설정 파일에서만 읽게 만든 이유** — 명령줄에 직접 쓰면
> **`ps` 목록에 그대로 보입니다.** 같은 폰에서 도는 다른 프로그램이 읽을 수 있습니다.
> 설정 파일은 **권한 600** 이라 주인만 읽습니다.

7장에서 **이 파일을 그대로** 자동 실행에 등록합니다 — 손으로 띄울 때와
자동으로 뜰 때가 **같은 파일**이라, 한쪽만 되는 일이 생기지 않습니다.

## 5. 미디어 서버 — Jellyfin

Jellyfin은 Termux에 바로 설치할 수 없어서, **폰 안에 데비안 리눅스를 올리고**
그 안에 설치합니다.

### 5-0. 🔑 dufs 는 그냥 깔렸는데 왜 얘는 데비안이 필요한가

**둘 다 리눅스 프로그램인데 하나는 바로 돌고 하나는 안 됩니다.** 차이는 여기 있습니다.

| | dufs | Jellyfin |
|---|---|---|
| 만든 언어 | Rust | **C#(.NET)** |
| 필요한 것 | **없음** — 혼자 다 들고 있습니다 | **.NET 런타임** + 리눅스 표준 라이브러리 |
| 실제로 찾는 파일 | — | `libc.so.6` · `ld-linux-aarch64.so.1` |
| 폰에 그게 있나 | — | 🔴 **없습니다** |

안드로이드도 **리눅스 커널**을 씁니다. 그런데 그 위에 올라가는 **기본 라이브러리가 다릅니다** —
안드로이드는 **bionic**(`libc.so`), 보통의 리눅스 배포판은 **glibc**(`libc.so.6`)를 씁니다.
🔑 **이름부터 다른 물건입니다.** 그래서 배포판용으로 만들어진 프로그램은 폰에서 **자기가 찾는
라이브러리를 못 찾고 시작조차 못 합니다.**

**dufs 는 그 문제가 아예 없습니다.** 필요한 걸 **전부 자기 안에 넣어서 만든**(정적 링크)
파일이라 바깥에서 찾을 게 없습니다. 그래서 받아서 바로 실행됩니다.

> 🔑 **그럼 `pkg install jellyfin` 은 왜 없나요** — Termux 저장소의 패키지들은
> **안드로이드용으로 다시 빌드한 것**입니다. 누군가 .NET 런타임을 통째로 안드로이드에
> 맞춰 옮겨야 하는데, **아직 없습니다.** (`pkg search dotnet` → 안 나옵니다)

**그래서 데비안을 가져옵니다.** `proot` 가 하는 일은 **glibc 를 포함한 배포판 한 벌을
폴더로 풀어놓고, 그 안에서는 그 폴더가 `/` 인 것처럼 보이게** 하는 것입니다.
Jellyfin 이 `libc.so.6` 을 찾으면 **그 폴더 안의 진짜 glibc** 를 만나게 됩니다.

🔴 **이건 1장의 "도커가 안 된다"와는 다른 이야기입니다.** 층이 다릅니다.

| | 막히는 지점 | 해결 |
|---|---|---|
| **Jellyfin** | **라이브러리**가 없다 (유저 공간) | ✅ **proot 로 해결됩니다** |
| **도커** | **커널 권한**이 없다 | 🔴 **해결 못 합니다** |

🔑 **유저 공간의 문제는 폴더를 가져오면 풀리고, 커널의 문제는 안 풀립니다.**
*"폴더를 아무리 꾸며도 커널은 속지 않는다"* 는 1장의 말이 여기서 정확히 선을 긋습니다.

⚠️ **느려서 손해 보는 건 아닙니다.** 이 구성에서 잰 값은 **기동 20.6초 · 재생 CPU 0~8% ·
온도 +0.2℃** 입니다(12장). proot 는 **성능 때문에 쓰는 게 아니라 유일한 방법이라서** 씁니다.
대신 **용량 약 500MB** 를 더 씁니다.

> 💡 **데비안을 깔기 싫다면** — 4장의 **dufs 로도 영상은 재생됩니다.** 브라우저가 직접
> 재생하기 때문입니다. 🔴 다만 **포스터·이어보기·자막 관리·계정별 시청기록이 없습니다.**
> 그게 필요 없다면 5장은 건너뛰어도 됩니다.

### 5-1. 한 줄로 — 데비안 설치부터 첫 실행까지

```bash
sh ~/install-jellyfin.sh
```

⏱ **처음이면 5~10분쯤 걸립니다.** 대부분 내려받는 시간이고, 진행 상황이 화면에 흐릅니다.

```
미디어 서버(Jellyfin) 설치
────────────────────────────────────────────
  ⏱ 처음이면 5~10분쯤 걸립니다. 대부분 내려받는 시간입니다.
     중간에 글자가 한동안 안 바뀌어도 멈춘 게 아닙니다.

  ✅ proot-distro 설치 완료
  ✅ debian 설치 완료 (52초)

  · Jellyfin 설치 중 — 내려받는 데 몇 분 걸립니다
    [1/4] 패키지 목록 갱신 (20초쯤)
    [2/4] 기본 도구 설치 (curl · gnupg)
    [3/4] Jellyfin 저장소 등록

    [4/4] Jellyfin 내려받기·설치 — ⏱ 여기가 가장 오래 걸립니다 (수백 MB)
  ✅ Jellyfin 설치 완료
  ✅ 라이브러리 바로가기 — /media/movies · /media/download · /media/phone
```

**마지막에 멈춰 있는 게 정상입니다** — Jellyfin이 떠 있는 상태입니다.
⏱ **첫 기동은 20~30초** 걸리고 `Startup complete` 가 나오면 됩니다.
브라우저로 **`http://<폰주소>:8096/`** 에 접속하세요 (다음 **5-2**).

> ✅ **여러 번 실행해도 안전합니다.** 이미 깔린 단계는 건너뜁니다.

#### 📂 이 스크립트가 실제로 하는 일

| 단계 | 하는 일 |
|---|---|
| ① | `proot-distro` 설치 |
| ② | **데비안 설치** — 약 500MB. 🔑 **이미 있는지는 "들어가 보는 것"으로 판단합니다.** 폴더 위치는 `proot-distro` 버전마다 달라서, 경로로 찾으면 버전이 바뀔 때 깨집니다 |
| ③ | 데비안 **안에서** 저장소 키를 등록하고 Jellyfin 설치 |
| ④ | 폰 저장소를 데비안에서 보이게 **바로가기 생성** |
| ⑤ | `~/start-jellyfin.sh` 로 넘겨 **포그라운드 실행** |

🔑 **③의 저장소 파일은 "지금 이 데비안에 맞춰" 만듭니다.** 코드명(`trixie`·`bookworm`…)과
아키텍처(`arm64`·`armhf`)를 직접 읽어서 씁니다 — 하나라도 안 맞으면 apt가
*"저장소에 그런 게 없다"* 며 설치를 거부하는데, **원인이 전혀 안 드러나는 자리**입니다.

🔴 **④의 바로가기가 없으면 라이브러리를 못 고릅니다.** Jellyfin 폴더 선택창에서
`/storage/emulated` 까지만 보이고 그 안의 `0` 이 안 보입니다. 안드로이드가 그 폴더에
**"통과는 되지만 목록은 못 읽는"** 권한(`drwx--x--x`)을 주기 때문입니다.

⚠️ 설치 중 `invoke-rc.d: policy-rc.d denied execution of start` 경고가 나오는데
**정상입니다.** 폰에는 systemd가 없어서 자동 기동만 못 할 뿐, 설치는 정상 완료됩니다.


#### 🔴 왜 포그라운드로 띄우나

데몬 모드로 띄우면 **터미널을 닫는 순간 같이 죽습니다.** 데비안은 `proot` 라는 도구
위에서 도는데, **그 도구가 끝나면 안쪽 프로그램도 함께 내려가기** 때문입니다.
7장에서 `runit` 이 이 포그라운드 프로세스를 대신 붙잡아 줍니다.

`~/start-jellyfin.sh` 가 그 포그라운드 실행을 맡는 파일이고, **7장에서 그대로**
자동 실행에 등록합니다 — 손으로 띄울 때와 자동으로 뜰 때가 **같은 파일**입니다.

### 5-2. 설정 마법사

`http://<폰주소>:8096/` 에 접속해서 계정을 만들고,
**미디어 라이브러리 추가 → 폴더 → `/media/movies`** 를 지정합니다.

> 🔴 **하드웨어 가속은 켜지 마세요.** 폰은 앱 권한 문제로 영상 디코더
> (`/dev/dri`, `/dev/video*`)에 접근할 수 없습니다. 켜봐야 동작하지 않습니다.
> **Direct Play**(원본 그대로 재생)로 쓰면 CPU 점유가 한 자릿수로 아주 가볍습니다.
> 라이브러리를 **H.264 + AAC** 로 맞춰두면 대부분 Direct Play로 재생됩니다.

## 6. 동기화 — 구글 드라이브 대신 (선택)

폰과 PC가 **같은 폴더를 서로 맞춰 들고 있게** 만듭니다. 한쪽에 파일을 넣으면
다른 쪽에 알아서 생깁니다. **Syncthing** 을 씁니다 — Termux 패키지로 바로 설치됩니다.

### 왜 구글 드라이브 대신 쓸 수 있나

| | 클라우드 저장소 | **Syncthing (이 폰)** |
|---|---|---|
| 요금 | 용량을 늘리면 **매달** 냅니다 | **0원** |
| 용량 | 요금제만큼 | **폰 저장공간만큼** (남은 용량 전부) |
| 파일이 있는 곳 | 업체 서버 | **내 폰** |
| 전송 | 업체 서버를 거칩니다 | **기기끼리 직접**(TLS 암호화) |
| 업체 계정 | 필요 | **없음** |

> 🔑 **폰 홈서버에 특히 잘 맞습니다.** 미디어 서버와 달리 **발열이 거의 없고**
> 파일이 바뀔 때만 움직입니다. "24시간 켜 둘 이유" 가 분명한 쪽입니다.

### 🔴 먼저 알고 쓰세요 — 클라우드와 다른 점

|                      |                                                                   |
| -------------------- | ----------------------------------------------------------------- |
| 🔴 **동기화는 백업이 아닙니다** | 한쪽에서 지우면 **다른 쪽에서도 지워집니다.** 되살리려면 폴더 설정에서 **파일 버전 관리**를 켜 두어야 합니다 |
| 🔴 **공유 링크가 없습니다**   | 남에게 파일을 링크로 주는 기능은 없습니다. 그건 4장의 파일 서버(`:8092`)가 합니다               |
| ⚠️ **기본은 폴더 전체**     | 기기마다 같은 내용을 **전부** 들고 있습니다. 일부만 빼려면 제외 패턴(`.stignore`)을 씁니다       |
| ⚠️ **양쪽이 다 켜져 있어야**  | 폰이 꺼져 있으면 그동안 바뀐 건 **다음에 켤 때** 맞춰집니다                              |

### 6-1. 한 줄로 — 설치부터 첫 실행까지

```bash

```

```

  ✅ GUI 주소 개방 — 0.0.0.0:8384
```

**마지막에 멈춰 있는 게 정상입니다** — Syncthing이 떠 있는 상태입니다.
브라우저로 들어가 확인하고 **`Ctrl+C`** 로 멈춥니다. 7장에서 자동 실행으로 등록합니다.

#### 🔑 주소가 `https` 입니다

```
https://<폰주소>:8384/
```

> 🔑 **`http` 로 치면 화면이 안 뜹니다.** 연결은 되는데 응답이 없어서 "설치가 잘못됐나"
> 싶어지는데, 그게 아닙니다. **Syncthing 은 폰 바깥에서 들어오는 접속에는 스스로
> HTTPS로 올립니다** — 비밀번호를 평문으로 보내지 않기 위해서입니다.
> 폰 자신이 열 때(`127.0.0.1`)는 `http` 가 맞습니다.
>
> ⚠️ **처음 열면 브라우저가 "안전하지 않음" 경고를 띄웁니다.** 스스로 만든
> 인증서라 그렇습니다. **고급 ▸ 계속 진행**으로 들어가면 됩니다.

로그인은 **4장에서 정한 아이디·비밀번호**입니다. 🔴 **비밀번호 없이 GUI를 열어두면
같은 Wi-Fi의 누구나 폰 안의 파일을 넣고 뺄 수 있습니다.** 이 폰의 서비스를
**하나의 계정으로 묶어** 두는 이유입니다.

#### 📂 이 스크립트가 실제로 하는 일

| 단계 | 하는 일 |
|---|---|
| ① | `pkg install syncthing` |
| ② | **설정·키 생성** — 🔑 비밀번호를 **표준입력**으로 넘깁니다. 명령줄에 쓰면 `ps` 목록에 그대로 보입니다 |
| ③ | GUI 주소를 `127.0.0.1` → `0.0.0.0` 으로. 기본값은 **폰 안에서만** 열립니다 |
| ④ | 🔴 **바깥에 알리는 기능 세 개를 끕니다** (아래) |
| ⑤ | `~/sync` 폴더를 만들고 `~/start-syncthing.sh` 로 넘깁니다 |

⚠️ **②는 설정이 없을 때만 합니다.** 이미 쓰던 설정을 덮어쓰지 않습니다.
다시 만들려면 `~/.local/state/syncthing` 을 지우고 실행하세요.

🔴 **돌고 있으면 스크립트가 멈추라고 말하고 끝납니다.** Syncthing 은 종료할 때
**자기 설정을 메모리 내용으로 덮어쓰기** 때문에, 켜 둔 채로 고치면 ③④가 **조용히
되돌아갑니다.** `sv down syncthing` 으로 멈춘 뒤 다시 실행하면 됩니다.

#### 🔴 ④ — 바깥에 알리지 않게 끄는 것

설치 직후 Syncthing은 **인터넷의 공개 서버에 자기 존재를 알립니다.** 집 밖에서
동기화할 때 쓰는 기능인데, **2장에서 Tailscale을 깔았으면 필요하지 않습니다.**

| 끄는 것 | |
|---|---|
| **전역 탐색**(Global Discovery) | 공개 탐색 서버에 기기 ID를 올립니다 |
| **릴레이 사용**(Enable Relaying) | 공개 중계 서버를 거쳐 연결합니다 |
| **NAT 통과**(NAT Traversal) | 공유기에 구멍을 내려고 시도합니다 |

**로컬 탐색(Local Discovery)은 켜 둡니다** — 같은 Wi-Fi 안에서 서로 찾는 기능입니다.

> 🔑 **끄면 LAN과 Tailscale 안에서만 동기화됩니다.** 노출이 줄고, 폰이 공개 서버와
> 상시 연결을 유지하지 않으니 **배터리·데이터도 덜 씁니다.** 폰 홈서버에서는
> 배터리가 핵심 변수입니다.
>
> 💡 **GUI에서도 확인할 수 있습니다** — **설정(Settings) ▸ 연결(Connections)**.
> 스크립트가 꺼둔 것이 실제로 꺼져 있는지 눈으로 보고 싶을 때 보세요.

## 7. 자동시작 — 이게 핵심입니다

여기까지는 **Termux를 열어둬야만** 서버가 돕니다. 이제 폰을 꽂아두기만 하면
알아서 뜨게 만듭니다.

### 7-1. 서비스 등록

앞서 받아둔 스크립트가 **지금까지 깐 서버를 runit에 등록**해 줍니다.

```bash
sh ~/setup-services.sh
```

20초쯤 뒤 상태가 출력됩니다. **전부 `run:` 이면 성공**입니다.

```
등록: dufs
등록: jellyfin
등록: syncthing

자동시작 켜는 중…

── 상태 (전부 run: 이면 성공) ──
run: sshd: (pid ...)
run: dufs: (pid ...)
run: jellyfin: (pid ...)
run: syncthing: (pid ...)
```

🔑 **4·5·6장에서 깐 서버 셋이 한 번에 등록됩니다.** 이 스크립트는 **깔려 있는 것만**
등록하므로, 건너뛴 장이 있으면 `건너뜀: …` 으로 알려줍니다. 나중에 그 장을 하고
**다시 실행하면** 그때 추가됩니다.

> 💡 **이름을 지정할 수도 있습니다** — `sh ~/setup-services.sh dash` 처럼요.
> 8장(카메라)과 부록 A 에서 그렇게 씁니다.

#### 이 스크립트가 만드는 것

서비스 하나당 폴더 하나입니다. **설정 파일이 따로 없고, 파일의 존재 자체가 설정**입니다.

```
$PREFIX/var/service/dufs/
├── run        ← 실행 스크립트 (이게 서비스 그 자체)
├── down       ← 이 파일이 있으면 자동시작 안 함 (sv-enable 이 지움)
├── supervise/ ← 상태 기록 (자동 생성)
└── log/run    ← 로그 처리기
```

> 🔑 **`run` 파일의 규칙 — 프로그램이 "포그라운드"로 떠 있어야 합니다.**
> `&` 를 붙이거나 데몬 모드(`daemon on` 등)로 띄우면, runit이 "프로그램이 끝났다"고
> 판단해서 **1초마다 무한 재시작**합니다. 그래서 `exec` 로 실행합니다.

#### 감시가 되는지 확인 (선택)

일부러 죽여보면 runit이 되살리는 걸 볼 수 있습니다.

```bash
pkill -f 'dufs --config'
sleep 10
sv status dufs
```

**pid가 바뀐 채로 다시 `run:`** 이면 정상입니다.

### 7-2. 🔴 Termux:Boot 앱을 **한 번 실행**

**앱 아이콘을 한 번 탭하세요.** 빈 화면이 잠깐 떴다 닫히는 게 전부지만,
**이걸 안 하면 자동시작이 절대 안 됩니다.**

> 🔴 **왜 그런가** — 안드로이드는 **설치 후 한 번도 실행되지 않은 앱**을
> "정지 상태"로 분류하고, **부팅 완료 신호를 아예 보내지 않습니다.**
> Termux:Boot은 신호를 놓친 게 아니라 **받을 자격이 없는 상태**였던 겁니다.
>
> 확인 방법: **설정 → 개발자 옵션 → 대기 중인 앱**에서 `com.termux.boot` 의 값이
> **`NEVER` 면 아직 안 된 것**이고, `ACTIVE` 등으로 바뀌면 된 것입니다.
> (개발자 옵션이 없으면: 설정 → 휴대전화 정보 → 소프트웨어 정보 → **빌드번호 7회 탭**)

### 7-3. 부팅 스크립트 설치

```bash
sh ~/install-boot.sh
```

```
부팅 자동시작 설치
────────────────────────────────────────────
  ✅ 옮김 — ~/boot-start-services.sh → ~/.termux/boot/start-services.sh

  들어간 내용:
      #!/data/data/com.termux/files/usr/bin/sh
      termux-wake-lock
      . /data/data/com.termux/files/usr/etc/profile.d/start-services.sh

  권한:
      -rwx------  ... start-services.sh

  ✅ Termux:Boot 앱 설치됨
```

내용은 두 줄뿐입니다.

| 줄 | 하는 일 |
|---|---|
| `termux-wake-lock` | 안드로이드가 **절전으로 재우지 못하게** 붙잡습니다 |
| `. start-services.sh` | **runit을 기동** → 등록된 서비스가 전부 따라 올라옵니다 |

> 🔴 **위치와 실행 권한, 둘 다 맞아야 합니다.** `~/.termux/boot/` 폴더 안에 있어야 하고,
> **실행 권한(`x`)이 없으면 Termux:Boot 이 그냥 무시합니다** — 에러가 안 나서
> 원인을 찾기 어려운 자리입니다. 그래서 스크립트가 **권한까지 찍어서 보여줍니다.**
>
> ✅ **여러 번 실행해도 안전합니다.** 이미 옮겼으면 "이미 있음" 으로 넘어가고,
> 받아둔 파일이 없으면 **직접 만들어 줍니다.**

#### 📝 직접 만들고 싶다면 (한 줄 명령)

스크립트가 하는 일은 결국 이것뿐입니다.

```bash
mkdir -p ~/.termux/boot && printf '%s
%s
%s
' '#!/data/data/com.termux/files/usr/bin/sh' 'termux-wake-lock' '. /data/data/com.termux/files/usr/etc/profile.d/start-services.sh' > ~/.termux/boot/start-services.sh && chmod +x ~/.termux/boot/start-services.sh && cat ~/.termux/boot/start-services.sh
```

마지막 `cat` 으로 내용이 제대로 들어갔는지 바로 확인됩니다.

### 7-4. 🔴 안드로이드 절전 설정 — 폰이 서버를 재우지 못하게

안드로이드는 **배터리를 아끼려고 앱을 재우고 지우는** 기능이 여러 겹 있습니다.
서버로 쓰려면 Termux를 그 대상에서 빼야 합니다.

#### 먼저 — 진단은 설정 화면이 아니라 **개발자 옵션**에서 합니다

설정 화면의 토글은 **왜 그렇게 되어 있는지 알려주지 않습니다.** 안드로이드가
앱을 어떻게 분류하고 있는지는 여기서만 정확히 보입니다.

```
설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호 7회 탭  (개발자 옵션 켜기)
설정 → 개발자 옵션 → 대기 중인 앱(Standby apps)
```

`com.termux` 와 `com.termux.boot` 을 찾아 값을 확인합니다.

| 값 | 의미 | 해야 할 일 |
|---|---|---|
| **EXEMPTED** | 🔑 절전 **완전 면제** | 그대로 두면 됩니다 (가장 좋은 상태) |
| **ACTIVE** | 최근 사용 중 | 정상 |
| WORKING_SET · FREQUENT · RARE | 점점 강하게 제한됨 | 아래 **배터리 최적화 제외** 적용 |
| **RESTRICTED** | 강하게 제한됨 | 반드시 해제해야 합니다 |
| 🔴 **NEVER** | **한 번도 실행된 적 없음** | **앱을 한 번 실행**하세요 (7-2) |

**목표 상태**

| 앱 | 되어야 할 값 |
|---|---|
| `com.termux` | EXEMPTED 또는 ACTIVE |
| `com.termux.boot` | **NEVER만 아니면 됨** |

> ⚠️ **앱 설정의 "백그라운드에서 실행" 토글이 회색이라고 당황하지 마세요.**
> 막혀서 회색인 게 아니라, **이미 면제 상태라 시스템이 통제 중이어서** 사용자가
> 못 바꾸는 경우가 많습니다. **회색인지가 아니라 버킷 값이 기준입니다.**

#### 배터리 최적화에서 제외 (삼성 One UI 기준)

**Termux · Termux:Boot · Tailscale 세 앱 모두** 적용합니다.

| 설정 | 경로 | 값 |
|---|---|---|
| 앱별 배터리 | 설정 → 애플리케이션 → **(앱)** → 배터리 | **제한 없음** |
| 절전 모드 | 설정 → 배터리 → **절전 모드** | **끄기** |
| 미사용 앱 절전 | 설정 → 배터리 → 백그라운드 사용 제한 | **끄기** |
| 절전 앱 목록 | 같은 화면 → 절전 앱 · 심층 절전 앱 | **세 앱을 목록에서 제거** |
| 적응형 배터리 | 설정 → 배터리 → 기타 배터리 설정 | **끄기** |

> 📌 **제조사마다 메뉴 이름이 다릅니다.** 샤오미는 "자동 시작", 화웨이는 "앱 시작 관리"
> 같은 별도 항목이 있습니다. 이름이 달라도 찾는 것은 같습니다 —
> **"이 앱은 배터리 절약 대상에서 빼라"** 는 설정입니다.
> 어느 메뉴를 눌렀든 **결과는 개발자 옵션의 버킷 값으로 확인**하면 됩니다.

#### Wi-Fi가 화면 꺼진 뒤에도 유지되는지

서버는 화면이 꺼진 상태로 돕니다. 이때 Wi-Fi가 끊기면 접속이 안 됩니다.

```
설정 → 연결 → Wi-Fi → ⋮ → 고급
   → "절전 중 Wi-Fi 켠 상태로 유지"  ✅  (항목이 있는 기종만)
```

> 📌 최근 안드로이드는 대부분 자동으로 유지합니다. 항목이 없으면 넘어가세요.
> `termux-wake-lock`(7-3)이 CPU를 깨워두기 때문에 실제로는 거의 문제되지 않습니다.

#### Termux:API 권한

배터리·온도를 확인하려면 필요합니다.

```
설정 → 애플리케이션 → Termux:API → 권한 → 필요한 항목 허용
```

확인:

```bash
termux-battery-status
```

JSON이 나오면 정상입니다.

#### 💡 화면은 꺼져도 됩니다

`termux-wake-lock`은 **CPU만** 깨워둡니다. **화면 자동 꺼짐은 그대로 두세요** —
화면이 켜져 있으면 전력만 더 쓰고 발열도 올라갑니다.

| 항목 | 권장 |
|---|---|
| 화면 자동 꺼짐 | **짧게** (기본값 그대로) |
| 충전기 | **상시 연결** |
| 케이스 | **벗기기** — 발열 해소에 유리합니다 |

### 7-5. 재부팅해서 확인

폰을 재부팅하고, **Termux를 열지 말고** PC에서 접속해봅니다.

```powershell
ssh phone
```

> ⏱ **1~2분 기다리세요.** 구형 폰에서는 부팅 완료 신호가 **1분 반** 정도
> 지나서 오는 경우가 흔합니다. 바로 안 된다고 실패로 판단하지 마세요.

접속되면 확인:

```bash
sv status sshd dufs jellyfin
```

### 7-6. 🔴 며칠 뒤를 위한 준비 — 되살리는 위젯

**여기까지 하면 재부팅에는 강해집니다. 그런데 재부팅이 아닌 경우가 하나 더 있습니다.**

안드로이드는 **메모리가 모자라면 백그라운드 프로세스를 걷어갑니다.** Termux 안에서 돌던
서버들은 안드로이드가 보기에 "앱"이 아니라 그냥 떠 있는 프로세스라, **수거 대상 중에서도
우선순위가 높습니다.** 실제로 겪은 모습은 이렇습니다.

| | |
|---|---|
| 폰 | 켜져 있고, 카메라 앱도 정상 |
| 서버 | 🔴 **전부 안 열림** (SSH·파일·Jellyfin·동기화 모두) |
| 재부팅 | **없었음** — 며칠 잘 돌다가 그냥 사라졌습니다 |
| 알림 | **없음** |

> 🔴 **`termux-wake-lock` 은 이걸 막지 못합니다.** 웨이크락은 **재우는 것**을 막는 장치이고,
> **메모리 부족 수거는 못 막습니다.** 둘은 다른 문제입니다.

막을 방법은 없지만 **1초 만에 되살릴 수는 있습니다.** 부팅 때 쓰는 스크립트를
홈화면 버튼으로 만들어 두면 됩니다.

**① `Termux:Widget` 앱** — 맨 앞의 "앱 5개"에서 같이 받으셨으면 넘어가세요.
안 받았다면 **F-Droid 에서** 지금 받습니다 (🔴 Termux 와 **같은 곳**이어야 합니다).
⚠️ `pkg install termux-widget` 같은 패키지는 **없습니다.** 앱만 있으면 됩니다.

**② 스크립트를 위젯 폴더에 넣습니다**

```bash
mkdir -p ~/.shortcuts
cat > ~/.shortcuts/서버-재기동.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
echo "서버를 다시 올립니다..."
echo
. "$HOME/.termux/boot/start-services.sh"
sleep 5
export SVDIR="$PREFIX/var/service"
sv status $(ls "$SVDIR")
echo
echo "창은 닫아도 서버는 계속 돕니다."
EOF
chmod -R 700 ~/.shortcuts
ls -l ~/.shortcuts/
```

> 🔑 **부팅 때와 똑같은 스크립트를 부릅니다.** 복구 방법을 두 가지로 만들지 않으려는 것이고,
> 덤으로 **이 버튼이 되면 부팅도 된다**는 뜻이 됩니다.
> ✅ **이미 서버가 돌고 있을 때 눌러도 안전합니다** — 돌고 있는 것은 건드리지 않습니다.

**③ 폰 홈화면에 위젯을 올립니다**

```
홈화면 빈 곳 길게 누르기 → 위젯 → Termux → 끌어다 놓기
   → 목록에 "서버-재기동.sh" 가 보입니다
```

이제 **안 열릴 때 그 버튼 한 번**이면 됩니다. 터미널이 열리고 `run:` 목록이 찍힙니다.

> 💡 **PC에서도 같은 걸 할 수 있습니다** — 접속이 되는 상태라면
> `sh ~/.shortcuts/서버-재기동.sh` 로 실행하면 됩니다. 🔴 단 **SSH 가 죽은 뒤에는
> PC에서 들어갈 수 없으니**, 위젯이 유일한 복구 수단입니다. 꼭 올려 두세요.

## 8. 카메라 — 밖에서 집 안 보기 (선택)

남는 폰의 가장 쓸 만한 용도입니다. **카메라가 이미 달려 있고, 충전기에 꽂혀 있고,
Wi-Fi에 붙어 있습니다.** 여기에 2장의 Tailscale이 붙으면 **밖에서 집 안을 볼 수 있습니다.**

```
폰 카메라 ──[ IP Webcam 앱 ]── MJPEG ──[ 대시보드 :8095 ]──▶ 브라우저
             하드웨어 인코딩              인증 + 중계
```

> 🔑 **왜 앱을 하나 더 깔아야 하나** — 0장에서 말한 그대로입니다.
> **Termux는 카메라를 열 수 없습니다.** 그리고 앱을 쓰는 편이 **결과도 훨씬 좋습니다**
> — 앱은 폰의 **하드웨어 인코더**를 쓰기 때문입니다. 리눅스 쪽에서 억지로 흉내내면
> (사진을 1장씩 찍어 이어 붙이는 방식) **초당 0.6장**에 **렌즈 초점 모터가 2초마다
> 계속 움직입니다.** 소리가 들릴 정도라 24시간 돌릴 수 없습니다.

### 8-1. IP Webcam 설치와 설정

Play 스토어에서 **IP Webcam**(Pavel Khlebovich)을 설치합니다. 앱을 열고 아래만 바꿉니다.

| 설정 | 값 | 이유 |
|---|---|---|
| 비디오 해상도 | **1280 × 720** | 1080p는 대역폭이 2.5배로 뜁니다 |
| 화질 | **40** 전후 | 올리면 그만큼 대역폭이 올라갑니다 |
| 🔴 **로그인 / 비밀번호** | **반드시 설정** | 아래 7-2 |
| 방향 | 가로(landscape) | |

설정이 끝나면 맨 아래 **"서버 시작"** 을 누릅니다. 화면에 접속 주소가 뜹니다.

> 💡 **"배터리를 아끼려면 화면을 끄세요"** 항목을 켜두면 화면만 꺼진 채로 계속 송출합니다.

> 🔴 **IP Webcam 도 배터리 최적화에서 제외하세요.** 7-4에서 Termux에 한 것과 **똑같이**
> 해줘야 합니다. 카메라 앱은 Termux 바깥이라, 안드로이드가 재우면 **runit이
> 되살려주지 못합니다.** 꺼지면 폰에서 직접 다시 켜야 합니다.

### 8-2. 🔴 비밀번호를 반드시 거세요

**카메라 앱의 포트(8080)는 집 Wi-Fi에 붙은 모든 기기에 열립니다.** 주소만 알면
누구나 집 안을 볼 수 있습니다. 이 가이드의 다른 서비스와 달리 **영상은 되돌릴 수 없습니다.**

앱에서 정한 아이디·비밀번호를 **폰에도 저장**해 둡니다. 다음 단계의 대시보드가
이 값을 읽어서 **대신 로그인**해 줍니다.

```bash
printf '%s' 'IP Webcam에서정한아이디'   > ~/.cam_user && chmod 600 ~/.cam_user
printf '%s' 'IP Webcam에서정한비밀번호' > ~/.cam_pass && chmod 600 ~/.cam_pass
```

### 8-3. 대시보드 — 카메라와 상태를 한 페이지에

여기까지 만든 것들이 **포트 번호로 흩어져 있습니다.** 한 페이지에 모읍니다.

| 칸 | 내용 |
|---|---|
| 📷 **카메라** | 실시간 영상 + 조명·렌즈·해상도·화질 설정 |
| 📊 **상태** | 배터리·온도·메모리·저장공간 |
| 🔗 **서비스** | 만든 서버들로 가는 링크 (살아 있는지도 함께 표시) |

🔑 **이 페이지는 "보는 곳"입니다.** 폰을 움직이는 버튼(진동·손전등·알림·음성)은
**부록 A 의 제어판(`:8094`)** 에 따로 있습니다 — 보는 것과 시키는 것을 섞지 않았습니다.
서비스 칸의 링크로 바로 건너갈 수 있습니다.

🔑 **파일은 이미 받아져 있습니다** — 「스크립트 내려받기」에서 `~/myapp/dashboard.py` 로 같이 왔습니다.

```bash
ls -l ~/myapp/dashboard.py     # 있는지만 확인합니다
```

> 💡 **없다면** `sh ~/get-files.sh` 를 다시 실행하세요. 이미 있는 파일은 그대로 두고
> 빠진 것만 다시 받습니다.

한 번 띄워서 확인합니다.

```bash
python ~/myapp/dashboard.py
```

브라우저로 `http://<폰주소>:8095/` 에 접속합니다. 로그인은 **4-1에서 정한
dufs 아이디·비밀번호**입니다. 영상이 보이면 **`Ctrl+C`** 로 멈춥니다.

> 🔑 **대시보드가 영상을 중계합니다.** 브라우저가 카메라 앱(8080)에 직접 붙지 않고
> 대시보드를 거칩니다. 그래서 **① 바깥에 열어둘 포트가 8095 하나로 줄고,
> ② 로그인 한 번으로 카메라까지 막힙니다.** 중계 비용은 **CPU 2%** 였고,
> 화질은 **전혀 손상되지 않습니다**(재인코딩 없이 그대로 흘려보냅니다).

### 8-4. 서비스로 등록

7장에서 쓴 **그 스크립트에 이름만 붙여** 부릅니다.

```bash
sh ~/setup-services.sh dash
```

`run: dash: (pid ...)` 가 나오면 끝입니다. 이제 **부팅할 때 알아서 뜨고, 죽으면 되살아납니다.**

### 8-5. ⚠️ 알고 쓸 것 — 대역폭

MJPEG는 **프레임마다 사진 1장을 통째로** 보냅니다. 구조가 단순한 대신 용량을 씁니다.

| 설정 | 실측 |
|---|---|
| 1280×720 · 화질 40 | **약 7 Mbps** · 29.9 fps |
| 1920×1080 | 약 17 Mbps |
| 🔴 **보는 사람 2명** | **2배** (14 Mbps) — 한 명씩 늘어날 때마다 그만큼 |

> 🔴 **혼자 볼 때를 전제로 한 구성입니다.** 여러 명이 동시에 보거나 24시간 녹화가
> 필요하면 이 방식은 맞지 않습니다. 그때는 폰이 아니라 **PC나 미니PC에
> 전용 소프트웨어**를 두는 쪽이 맞습니다.

### 8-6. 안 되는 것

| | |
|---|---|
| 🔴 **녹화 · 움직임 감지** | 이 구성은 **보는 것**까지입니다 (IP Webcam 앱 자체 기능은 별개) |
| 🔴 **카메라 앱 자동 복구** | 앱은 Termux 바깥이라 **runit이 못 살립니다.** 꺼지면 폰에서 직접 켜야 합니다. 대시보드가 **꺼진 걸 알려주기는** 합니다 |
| ⚠️ **카메라는 하나** | 다른 앱이 카메라를 쓰면 밀려납니다 |

## 10. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| **`No such file or directory`** — 스크립트가 없다고 나온다 | 「스크립트 내려받기」를 안 했거나 그때 일부가 실패한 것. **`sh ~/get-files.sh`** 를 다시 실행하세요. 이미 있는 파일은 두고 **빠진 것만 다시 받습니다** |
| **재부팅 후 아무것도 안 뜬다** | Termux:Boot 앱을 한 번도 실행하지 않음 → **7-2** 참조. 개발자 옵션에서 `NEVER` 인지 확인 |
| **1분쯤 기다려도 안 뜬다** | 조금 더 기다려보세요(구형 폰은 +90초도 정상). 그래도 안 되면 6-2·6-3을 다시 확인 |
| **잘 돌다가 몇 시간 뒤 죽어 있다** | 배터리 절전이 앱을 재운 것. **7-4**의 배터리 최적화 제외를 적용하고, 개발자 옵션에서 버킷이 `RARE`·`RESTRICTED` 로 떨어지지 않았는지 확인 |
| 🔴 **며칠 뒤 서버가 전부 안 열린다** (폰은 켜져 있고 다른 앱은 정상) | **안드로이드가 메모리를 확보하려고 걷어간 것**입니다. 재부팅도, 알림도 없이 일어납니다. 🔑 **막을 수는 없고 되살리면 됩니다 — 7-6의 위젯 한 번.** ⚠️ 버킷·절전 설정을 아무리 봐도 원인이 안 나옵니다(그쪽 문제가 아닙니다). `termux-wake-lock` 도 이건 못 막습니다 |
| **"백그라운드에서 실행" 토글이 회색이다** | 막힌 게 아니라 **이미 면제 상태**일 수 있습니다. 토글 색이 아니라 **개발자 옵션의 버킷 값**으로 판단하세요(7-4) |
| **화면이 꺼지면 접속이 끊긴다** | Wi-Fi 절전. **7-4**의 Wi-Fi 항목 확인. `termux-wake-lock` 이 실행됐는지도 확인(알림창에 Termux 상주 표시) |
| `termux-battery-status` 가 안 된다 | Termux:API **앱**과 `termux-api` **패키지**는 별개입니다. 둘 다 있어야 하고, 앱 권한도 허용해야 합니다(7-4) |
| `sv: unable to change to service directory` | ① `termux-services` 설치 후 **Termux를 재시작**하지 않음 ② 🔑 **PC에서 `ssh` 로 명령 한 줄만 실행한 경우** — 그 셸에는 `SVDIR` 이 없습니다. `export SVDIR=$PREFIX/var/service` 를 먼저 실행하세요. **서비스는 정상인데 `sv` 명령만 실패**하는 것이라 오진하기 쉽습니다 |
| `down: <서비스> ... want up` 반복 | 같은 포트를 쓰는 프로세스가 이미 떠 있음. `pkill` 또는 PID로 종료 |
| **서비스가 계속 재시작된다** | `run` 스크립트가 **포그라운드가 아님**. `&` 나 데몬 모드를 빼고 `exec` 사용 |
| 🔴 **`sv restart jellyfin` 이 `timeout` 으로 끝난다** | Jellyfin 은 `proot` 안에서 돌아서 **종료 신호가 안쪽까지 전달되지 않습니다.** 겉보기엔 멈춘 것 같지만 그대로 돌고 있습니다. 안쪽 프로세스를 직접 끝내면 `runit` 이 알아서 다시 띄웁니다: `kill -9 $(pgrep -f "usr/bin/jellyfin --webdir")` |
| 🔴 **받은 스크립트가 `set: Illegal option -` 로 죽는다** | 줄바꿈이 **윈도식(CRLF)** 인 파일입니다. 윈도 PC를 거쳐 옮겼다면 생깁니다. 고치기: `sed -i 's/\r$//' ~/파일이름.sh` |
| 🔴 **`Failed to get local interface addresses` / `Permission denied (os error 13)`** | **안드로이드 11 이후 기기**에서 납니다. 서버가 "어떤 주소로 열렸는지" 보려고 인터페이스 목록을 읽는데 안드로이드가 막습니다. 🔑 **`start-dufs.sh` 는 이걸 알아서 처리합니다** — 실패하면 실제 주소를 찾아 다시 엽니다(`📌 … 실제 주소로 다시 엽니다` 가 보이면 정상). 안 고쳐지면 스크립트를 다시 받으세요: `sh ~/get-files.sh` |
| **Syncthing 화면이 안 뜬다**(연결은 되는데 빈 화면) | 🔑 **`http` 로 접속한 것.** 폰 바깥에서는 **`https://<폰주소>:8384/`** 입니다(6-1). 인증서 경고는 **고급 ▸ 계속 진행** |
| **Syncthing에 "폴더 경로 오류" 가 보인다** | `generate` 가 남긴 **빈 폴더 항목**. `sh ~/install-syncthing.sh` 가 지워줍니다 — 🔴 먼저 `sv down syncthing` 으로 멈추고 실행하세요 |
| **Syncthing이 PC를 못 찾는다** | 같은 Wi-Fi면 **로컬 탐색**이 켜져 있어야 합니다(6-1에서 끄지 말라고 한 항목). 밖에서 쓸 거면 **양쪽 다 Tailscale**에 들어와 있어야 합니다 |
| **데비안 안에서 띄운 프로그램이 금방 죽는다** | 터미널을 닫으면 같이 죽습니다. **runit 서비스로 등록**하면 해결됩니다(6-1) |
| **Jellyfin 폴더 선택창에 저장소가 안 보인다** | 안드로이드 권한 구조 때문. `/media/movies` 같은 **바로가기**를 골라야 합니다(5-1의 ④단계가 만들어 둡니다). 없으면 `sh ~/install-jellyfin.sh` 를 다시 실행하세요 |
| **밖에서 접속이 안 된다** | Tailscale 앱이 안 떠 있음. **3번의 "항상 켜진 VPN"** 확인 |
| **플러그인이 아무 반응이 없다** | Termux와 플러그인의 **설치처가 다름**. 넷 다 같은 곳에서 다시 설치 |
| **대시보드에 "카메라 앱이 꺼져 있습니다"** | IP Webcam이 종료된 상태. 폰에서 앱을 열어 **서버 시작**. runit은 앱을 되살릴 수 없습니다(7-6) |
| **대시보드는 뜨는데 영상만 검다** | 앱에 건 비밀번호와 `~/.cam_user`·`~/.cam_pass` 가 다름. 다시 저장하고 `sv restart dash` |
| **영상이 뚝뚝 끊긴다** | 대역폭. 해상도를 **640×480**, 화질을 **20**으로 낮춰보세요(7-5) |
| **영상이 몇 분 뒤 멈춘다** | 폰 화면이 꺼지며 앱이 재워진 것. IP Webcam을 **배터리 최적화에서 제외**(6-4와 동일하게) |

### 상태 확인에 쓰는 명령


## 부록 A. 내가 만든 스크립트를 서버로 — Python · Node.js

> 👩‍💻 **개발을 하시는 분들께.** 여기까지 만든 구조(runit)는 **남이 만든 프로그램 전용이
> 아닙니다.** 내가 짠 Python·Node 스크립트도 똑같이 **부팅 자동 시작 + 죽으면 자동 복구 +
> 로그 수집**이 됩니다. 남는 폰이 **내 개인 API 서버**가 되는 셈입니다.

### A-1. 런타임 설치

**Python 은 1장에서 이미 깔았습니다**(7장 대시보드가 씁니다). **Node 만 추가합니다.**

```bash
pkg install -y nodejs-lts
python --version && node --version
```

> 📌 Termux 저장소는 꽤 최신입니다 — 이 문서 작성 시점 기준 Python 3.14 · Node 24 LTS.
>
> 💡 **Node 를 1장이 아니라 여기서 까는 이유** — 7장까지는 쓰이지 않습니다.
> 🧭 **센서 대시보드(Python)만 보고 싶다면 Node 는 건너뛰어도 됩니다.**
> 🔦 제어판(`control.js`)이 Node 로 되어 있어서, **그걸 쓸 때만** 필요합니다.

### A-2. 예제 서버 받기

🔑 **이것도 이미 받아져 있습니다** — 「스크립트 내려받기」에서 함께 왔습니다.

```bash
ls -l ~/myapp/
```

> 💡 **없다면** `sh ~/get-files.sh` 를 다시 실행하세요.

| 파일 | 포트 | 내용 |
|---|---|---|
| **`sensors.py`** | **8093** | 🧭 **폰 센서 대시보드** — 폰에서 **읽는다** (아래 **A-2-1**) |
| **`control.js`** | **8094** | 🔦 **폰 제어판** — 폰을 **움직인다** (아래 **A-2-2**) |
| `server.py` · `server.js` | 8093 · 8094 | 가장 단순한 예제. 위 둘과 **포트가 같으니 둘 중 하나**만 띄웁니다 |

🔑 **두 앱이 한 쌍입니다.** 하나는 폰이 **보는 것**(센서)을, 하나는 폰이 **하는 것**(토치·진동·
음성)을 보여줍니다. 둘을 합쳐야 *"폰이라서 되는 것"* 이 다 드러납니다.

#### A-2-1. 🧭 폰 센서 대시보드 — **미니PC가 못 하는 것**

```bash
python ~/myapp/sensors.py
```

브라우저로 `http://<폰주소>:8093/` 에 들어가면 **나침반 바늘이 실제로 돌아갑니다.**

| 보여주는 것 | 어디서 나오나 |
|---|---|
| 🧭 **나침반** | 지자기 센서 — 방위와 자기장 세기 |
| 💡 **조도** | 광센서 — `깜깜함 / 어두움 / 실내 조명 / 창가·야외` |
| 🌡 **기압 · 고도** | 기압계 — 표준대기 환산 고도 |
| 📐 **기울기** | 가속도계 — 폰이 누웠는지 섰는지 |
| 👣 **걸음 수** | 걸음 센서 |
| 🤚 **근접** | 근접 센서 — 화면 위에 손을 대면 바뀝니다 |

🔑 **이게 라즈베리파이와 갈리는 지점입니다.** 같은 걸 하려면 센서 보드를 따로 사서
붙여야 하는데, **폰에는 원래 다 들어 있습니다.** 안 쓰는 폰을 서버로 쓸 때의
진짜 이점이 여기입니다.

**이 스크립트가 신경 쓴 것 세 가지**

| | |
|---|---|
| 🔑 **센서를 한 번에 묶어 읽습니다** | `termux-sensor` 는 **호출 한 번에 약 1.1초**가 듭니다. 그런데 그 비용은 **호출당**이지 센서당이 아닙니다(실측: 1개 1.1초 / 3개 1.1초). 따로 부르면 6종에 7초가 걸려 실시간이 안 됩니다. **하나의 스트리밍 프로세스**로 묶으면 **0.4초 간격**으로 갱신됩니다 |
| 🔑 **보는 사람이 없으면 센서를 끕니다** | 화면을 연 사람이 있을 때만 돌립니다. 🔴 폰 서버에서 제일 비싼 건 CPU가 아니라 **배터리와 열**입니다 |
| 🔑 **센서 이름을 박아두지 않습니다** | 부품 이름이 기종마다 다릅니다(`TMD4906 lux Sensor` 는 갤럭시 것). `termux-sensor -l` 로 **열쇳말로 찾아** 있는 것만 보여줍니다 |

> 🔴 **Termux:API 앱과 `termux-api` 패키지가 둘 다 있어야 합니다**(1장). 하나만 있으면
> **센서를 0종 찾았다**고 나옵니다.
>
> ⚠️ **고도가 음수로 나와도 고장이 아닙니다.** GPS 고도가 아니라 **기압을 환산한 값**이고,
> 기준이 1013 hPa 라서 기압이 높은 날은 음수가 됩니다. 화면에도 그렇게 적어뒀습니다.
> 🔑 **기압계로 고도를 재는 방법의 한계**를 그대로 보여주는 자리입니다.
>
> 💡 **나침반은 폰을 눕힌 상태 기준**입니다. 세우면 값이 틀어집니다 —
> 제대로 하려면 가속도계로 기울기를 보정해야 하는데, 그건 이 예제의 범위 밖입니다.

#### A-2-2. 🔦 폰 제어판 — 브라우저에서 누르면 폰이 반응합니다

```bash
node ~/myapp/control.js
```

`http://<폰주소>:8094/` 에 들어가 버튼을 누르면 **저쪽에 있는 폰이 바로 반응합니다.**

| 버튼 | 폰에서 일어나는 일 |
|---|---|
| 📳 **진동** | 폰이 진동합니다 |
| 🔦 **손전등** | 플래시가 켜지고 꺼집니다 |
| 🔔 **알림** | 적어 보낸 글자가 폰 알림으로 뜹니다 |
| 🔊 **말하기** | 폰이 그 문장을 **소리 내어 읽습니다** |

🔑 **센서 대시보드와 정확히 반대쪽입니다.** 저쪽이 "폰이 보는 것"이면 이쪽은 "폰이 하는 것"입니다.
🎬 **다른 방에 둔 폰이 소리를 내고 불이 켜지는 것**을 한 화면에서 보는 게 이 앱의 재미입니다.

**🔴 이 앱이 신경 쓴 보안 두 가지**

하드웨어를 건드리는 앱이라 그냥 열어두지 않았습니다.

| | |
|---|---|
| 🔴 **로그인을 겁니다** | 4장에서 만든 `~/.webdav_user` · `~/.webdav_pass` 를 그대로 씁니다. 없으면 경고를 찍습니다 |
| 🔴 **받은 글자를 쉘에 넘기지 않습니다** | `execFile` 로 **인자 배열**을 넘깁니다 |

> 🔑 **두 번째가 특히 중요합니다.** 문자열을 이어 붙여 `sh` 에 주는 방식이었다면,
> 입력칸에 **`; rm -rf ~`** 를 적어 보내는 것만으로 폰의 홈 폴더가 날아갑니다.
> 이 가이드에서 **"받은 값을 그대로 실행하면 안 된다"** 가 실제 코드로 나오는 유일한 자리입니다.
>
> 💡 **직접 확인해봤습니다** — 입력칸에 쉘 명령을 섞어 보내도 **글자 그대로** 전달되고,
> 명령으로 실행되지 않습니다.

> ⚠️ **클립보드는 넣지 않았습니다.** `termux-clipboard-set/get` 이 **Android 10에서
> 빈 값만 돌려줍니다**(앞에 띄워놔도 마찬가지였습니다). 안드로이드가 클립보드 접근을
> 조이면서 막힌 것으로 보입니다. 🔑 **되는 척하는 버튼을 두는 것보다 빼는 게 낫습니다.**

### A-3. 서비스로 등록

7장에서 쓴 **그 스크립트에 이름만 붙여** 부릅니다.

```bash
sh ~/setup-services.sh pyapp nodeapp
```

| 서비스 | 포트 | 실행하는 것 |
|---|---|---|
| `pyapp` | 8093 | 🧭 `sensors.py` — 센서 대시보드 |
| `nodeapp` | 8094 | 🔦 `control.js` — 폰 제어판 |

**둘 다 `run:` 이면 끝입니다.** 부팅할 때 알아서 뜨고, 죽으면 되살아납니다.

> 💡 **가장 단순한 예제(`server.py`·`server.js`)를 대신 띄우고 싶다면**
> `$PREFIX/var/service/pyapp/run` 의 파일 이름만 바꾸면 됩니다.
> 포트가 같아서 **한 포트에 하나만** 띄울 수 있습니다.

> 🔴 **Node 를 안 깔았으면** `nodeapp` 은 "건너뜀" 으로 나옵니다 — **A-1 을 먼저** 하세요.

### A-5. 실제로 쓸 때

| 할 수 있는 것 | 비고 |
|---|---|
| Flask · FastAPI · Express | `pip install` · `npm install` 그대로 동작 |
| SQLite | 파일 기반이라 문제없음 |
| 텔레그램 봇 · 디스코드 봇 | **바깥으로 거는 연결**이라 포트 제약이 없음 — 폰에 아주 잘 맞습니다 |

| 주의 | 이유 |
|---|---|
| 🔴 **1024 미만 포트 불가** | 80·443을 못 씁니다. **8000번대**를 쓰세요 |
| ⚠️ C 확장 패키지 빌드가 느림 | numpy·pandas 등은 휠이 없으면 컴파일에 오래 걸립니다 |
| ⚠️ 메모리 | 다른 서비스와 나눠 씁니다. `free -m` 으로 여유를 보고 올리세요 |
